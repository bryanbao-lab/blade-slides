# BLADE V2 方法论

## 1. 建立事实集合

开始前收集：已验收页面渲染图；可信模板或可编辑基线；准确画布与字体规则；真实 Logo 和身份关键照片；用户要求移动的对象与可接受固定的视觉；已验收页面的 QA 证据。

已验收渲染图是视觉真相；已验收 PPTX 是局部优化时的文件与图层基线。

## 2. 选择生产模式

- **Full rebuild：** 新页面或整批扁平设计稿。逐页构建、逐页验证，只有合格页面才能合并。
- **Local refinement：** 修改已验收 deck。必须记录基线、允许调整页、受保护页以及保护比较方法；只修失败的系统或对象。
- **Review draft：** 仅供紧急内容审阅。允许全页图+文字覆盖，但须标为草稿，永远不能通过 BLADE final。

## 3. 每个元素的拆分决策树

1. 用户是否要编辑文字？使用 `native_text`。
2. 是否为普通边框、直线、卡片、坐标轴或连接线？使用 `native_shape`。
3. 是否具备光学材质、身份关键图片、金属/玻璃处理或复杂灯光？把它作为一个有意义的 `transparent_png`。
4. 是否受场景透视或遮挡强绑定，且用户不需要移动？使用 `fixed_scene_visual` 或放入 `clean_base`。
5. 分离后是否必须带环境像素、碎弧或大量切片？扩大有意义复合边界或保持固定。

不能为了增加对象数量而选择表达方式。

## 4. 先保护已验收的重复系统

识别标题与阶段 icon 的位置、共同卡片壳体和标题、Logo wall 网格与 cell、圆章直径与 inset、视觉锚点、图表节点与标注语言、已验收的品牌 Logo 与页脚规则。量取一个合格母件，记录并复用 `reuse_key`。

## 5. 构建干净底图

只移除 `user_requested_movable` 的对象；无需编辑的成功源像素保留。暴露出来的环境应自然补全；若常规修图会留下补丁，应进行 source-preserving 图像编辑。

`clean_base` 中不得有：可移动对象的第二副本或阴影、环境本应连续处的填充矩形、被抹去的场景细节/变形建筑、重生成的身份关键照片或 Logo。

## 6. 构建有意义的前景模块

- **面板：** 普通几何用原生形状；切角、金边、玻璃、软阴影难以保真时，用带完整边框和安全边距的透明壳体，文字/icon 仍独立。
- **标题框+正文框：** 来自同一几何规格；接缝、切角、线宽和总宽必须一致。
- **圆形图片/圆章：** 从大于目标尺寸的源裁切开始，先复原完整圆环再缩小；统一直径并留 inset。
- **Logo wall：** 将大面板、标题条、cell 壳体和真实 Logo 分开，用同一测量网格。
- **图表与标注：** 网格、轴、数据线、标签、普通连接线原生化；金属节点或复杂箭头外壳使用透明资产；所有标注锚到准确数据点。
- **Hero visual：** 原生重画会降低品质时，保留一个高保真复合资产；可编辑文字和明确可移动 icon 放在其上方。

## 7. 命名与装配

所有重要对象采用语义化 PowerPoint 名称；控制 z-order；重复模块共享命名模式和 `reuse_key`。除非 group 本身就是用户的移动单位，不要用 group 妨碍普通编辑；避免会触发 Office Repair 的自定义几何或 XML hack。

## 8. 增量验证

每页检查干净底图、黑/白/棋盘格上的透明资产、move-away 证据、Selection Pane 名称、源图/渲染图叠加和关键 crop、准确文字与易混字符、真实 PowerPoint 导出。局部优化还须在最终包装前比较受保护页面与基线的新鲜渲染。

## 9. 只做一次最终定稿

先在 Microsoft PowerPoint 中打开、保存和导出，再技术 QA 与 SHA-256。记录哈希后，不得再用可能改写文件的应用打开它。
